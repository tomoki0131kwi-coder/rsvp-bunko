# RSVP文庫

青空文庫の作品を **RSVP（Rapid Serial Visual Presentation／高速逐次提示）** で読む Web アプリです。
文章を文節ごとに画面の中央へ次々と表示するので、視線を動かさずに読めます。

サーバーは不要で、ビルドすると静的ファイルだけになります（GitHub Pages などにそのまま置けます）。

## できること

- **作品検索**: 青空文庫の図書目録（公開中の全作品）を作品名・読み・作家名で検索。ひらがな・カタカナどちらでも引けます
- **括りから探す**（`#/browse`）: 次の括りを組み合わせて絞り込み、作品名・作家名・長さ・公開日の順に並べ替えて選べます。各選択肢には、ほかの条件を満たす作品の件数を表示します。条件は URL に入るので、ブックマークや共有もできます
  - ジャンル（分野・形式）: 図書目録の「分類番号」（日本十進分類法 NDC）による。文学は日本文学・英米文学などの言語別、それ以外は哲学・歴史などの類別。形式は小説・物語、詩歌、戯曲、評論・随筆、日記・紀行など
  - 対象: 分類番号に「K」が付く作品を児童書とする
  - 長さ: 本文ファイルの大きさから見積もった文字数（〜3千字、〜1万字、〜3万字、〜10万字、それ以上）。一覧には設定中の速さで読んだときの所要時間も表示
  - 作家の生まれた時代（江戸時代以前・明治・大正・昭和以降）、文字遣い、作品名の頭文字（五十音の行）
  - 作家: 作品一覧の作家名から、その作家の作品だけを表示
- **作家一覧**（`#/authors`）: 五十音順。名前で絞り込み、行ごとに移動できます
- **RSVP 表示**
  - 文節区切りには Google の [BudouX](https://github.com/google/budoux) を使用。指定した文字数（既定 8 文字）まで文節をまとめて表示
  - ルビ（ふりがな）表示、傍点、外字画像に対応
  - 句読点・段落末・見出し・場面転換で自動的に間を置く（強さは調整可）
  - 横書き／縦書きの切り替え
- **操作**: 再生・一時停止、1 つ戻る／進む、前後の文頭へ、前後の見出しへ、シークバー、目次
- **一時停止中は前後の文章を表示**。文節をクリックするとそこへ移動
- **読書位置の保存**: 「続きを読む」から再開。本文も端末（IndexedDB）に保存するので、一度開いた作品はオフラインでも読めます
- **ファイル・URL から開く**: 青空文庫の ZIP／ルビ付きテキスト／XHTML ファイルや、図書カードの URL
- ライト／セピア／ダークテーマ、スマートフォン対応、再生中のスリープ防止（Screen Wake Lock 対応ブラウザ）

### キーボード操作

| キー | 動作 |
| --- | --- |
| `Space` / `K` | 再生・一時停止 |
| `←` `→`（縦書きでは逆）／ `J` `L` | 1 つ戻る／進む |
| `Shift` + `←` `→` | 前の文頭／次の文頭 |
| `↑` `↓` | 速くする／遅くする（50 字/分刻み） |
| `[` `]` ／ `PageUp` `PageDown` | 前の見出し／次の見出し |
| `Home` | 先頭へ |
| `Esc` | 一時停止（停止中ならホームへ） |

## 開発

```bash
npm install
npm run catalog   # 図書目録 public/catalog.json を作る（要ネットワーク）
npm run dev       # 開発サーバー
npm test          # 単体テスト（Vitest）
npm run build     # dist/ に静的ファイルを出力
npm run preview   # ビルド結果の確認
```

### GitHub Pages への公開

`.github/workflows/deploy.yml` が `main` ブランチへの push でテスト・ビルドし、GitHub Pages に公開します。
初回はリポジトリの **Settings → Pages → Build and deployment → Source** を「GitHub Actions」にしてください。
出力は相対パス（`base: './'`）なので、`https://<ユーザー名>.github.io/rsvp-bunko/` のようなサブパスでも動きます。

## 仕組み

### 作品データの取得元

青空文庫のサイト（`www.aozora.gr.jp`）は CORS ヘッダーを返さないため、ブラウザから直接ファイルを取得できません。そこで次のようにしています。

- **図書目録**: デプロイ時（GitHub Actions）に `scripts/build-catalog.ts`（`npm run catalog`）が、青空文庫の
  「公開中　作家別作品一覧拡充版：全て」（`https://www.aozora.gr.jp/index_pages/list_person_all_extended_utf8.zip`）を取得し、
  `public/catalog.json` に変換してアプリと一緒に配信します。サーバー側で取得するので CORS の制約を受けません。
  デプロイ用ワークフローは毎週月曜にも動き、目録を作り直します
- **本文**: [aozorahack/aozorabunko_text](https://github.com/aozorahack/aozorabunko_text)（青空文庫の ZIP 内のテキストを
  `cards/<人物ID>/files/<ZIP名>/<ZIP名>.txt` に展開して公開しているリポジトリ）を `raw.githubusercontent.com` 経由で取得します。
  目録作成時にこのリポジトリのファイル一覧（本文は取らない）を取り、各作品に本文のパスを付けます。
  本文ファイルの大きさ（長さの目安）は GitHub API の git/trees から取ります（ワークフローの `GITHUB_TOKEN` を使用）。目録の ZIP と同じ版が無い場合は、ミラーにある版のうちルビ付き・版番号の大きいものを使います
- **ミラー未収録の作品**: 検索結果に「本文ミラー未収録」と表示し、開こうとすると図書カードへのリンクを出します。
  図書カードからダウンロードした ZIP を「ファイルを開く」で読み込めば読めます
- **外字画像**: `<img>` で青空文庫のサイトから直接表示します（画像の表示には CORS は不要）

本文の取得元は設定画面の「詳細設定」で、同じ構成のミラーに変更できます。

ローカルで開発するときは、先に `npm run catalog` で `public/catalog.json` を作ってください（`CATALOG_ZIP` に取得済みの ZIP を指定するとダウンロードを省けます）。

### 本文の解析（`src/aozora/`）

- `decode.ts` — 文字コード判定（XML 宣言・meta の charset、無ければ UTF-8 として読めるかで判定）。青空文庫のファイルは主に Shift_JIS
- `parseHtml.ts` — XHTML 版。`div.main_text` 内の `<br />` を行区切りとし、ルビ（`ruby`/`rb`/`rt`）、見出し（`o-midashi`/`naka-midashi`/`ko-midashi`）、注記（`span.notes`、除去）、外字（`img.gaiji`）、傍点（`em.sesame_dot`）を扱う
- `parseText.ts` — ルビ付きテキスト版。`《》` のルビ、`｜` によるルビ範囲指定、`［＃…］` の注記、`※［＃…］` の外字、見出し注記、`［＃改ページ］`、冒頭の記号説明ブロック、末尾の「底本：」以降の書誌情報を扱う

### 表示単位と表示時間（`src/rsvp/`）

- `chunker.ts` — BudouX で文節境界を求め、ルビ・外字の内側では区切らないよう調整。句読点や閉じ括弧だけの断片は前に、開き括弧は後ろにくっつけ、文をまたがない範囲で目安の文字数まで文節をまとめる
- `timing.ts` — 表示時間 = 1 文字あたりの時間（60000 ÷ 字/分）×（句読点・括弧を除いた文字数、最低 2 文字）＋ 区切りに応じた間（読点 1.5 字分、句点 3 字分、段落末 2.5 字分、見出し 4 字分、場面転換 6 字分）× 間の強さ
- `player.ts` — 上記の時間で表示を送る再生器。再生開始直後の 3 つは少しゆっくり表示（1.6 倍・1.35 倍・1.15 倍）

読書位置はチャンク番号ではなく本文中の文字位置で保存するので、表示単位の設定を変えても位置がずれません。

## 既知の制約

- 挿絵は表示しません。外字は Unicode で表せるもの（注記に `U+XXXX` があるもの）は文字に、それ以外は青空文庫の外字画像で表示し、画像が取れなければ「〓」になります
- 漢文の返り点は省略します。字下げ・字詰め・割り注などのレイアウト注記は反映しません
- 本文ミラー（aozorahack/aozorabunko_text）は 2023 年 3 月 22 日のコミットを最後に更新が止まっています。それ以降に公開・修正された作品は、ミラーに無いか旧版になります。読めない作品は、青空文庫からダウンロードしたファイルを「ファイルを開く」で読み込んでください
